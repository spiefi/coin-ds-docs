## Contract

- Props: `children` (one slot; every child gets the sheet's `modes`, without Page type except for an AppBar, and without Color Mode Dark), `accessibilityLabel` (names the dialog; else a slot child's `title` prop), `modes` (`Page type` only: MainPage and SubPage white, JioPlus `#f5f5f5`; Color Mode doesn't change the sheet), `fillHeight` (true: fill the parent; false: fit the content), `visible`, `showOverlay` (false), `onOverlayPress`, `onRequestClose` (drag-down only), `enableDismissGesture` (true), `onDismissed`, `topInset` (40 on iOS, 0 elsewhere), `presentationProgress`, `style`, and View props (`testID` lands on the sheet surface).
- With `visible` omitted it renders in flow: the surface and its slot. With `visible` set it fills its nearest positioned parent as an overlay: the sheet slides up from below on Reanimated's `withSpring` with `SPRING_CONFIG` (`ModalSheet.tsx:27-35`: damping 32, stiffness 300, mass 1, rest thresholds 0.1; a damping ratio of 0.92, so it settles without a visible bounce; the same spring as Drawer and ContentSheet), `presentationProgress` and an optional scrim (`rgba(0,0,0,0.7)`, a button named “Dismiss overlay”) follow a 220 ms `withTiming` (Reanimated's default ease-in-out), a drag moves the sheet and the progress with the finger, and a drag down past a quarter of the travel or a downward fling calls `onRequestClose`. `visible={false}` keeps it mounted below the screen. It is not a Modal or portal; the screen sets `visible` to false on every close.
- No title, handle, close button, footer, or focus handling. Since c1fa197 the sheet is `role="dialog"` (in flow, and the presented surface) and, on the web, Escape calls `onRequestClose` while it is shown, except when focus is in a text input (react-native-web's TextInput stops the keydown). Compose an App Bar with a named close IconButton at the top of the slot.
- Tokens: padding 12 / 8 / 32 / 8, radius 20 on all corners, `modalSheet/gap` 12 between slot children (c1fa197; before, it sat on the surface, whose only child is the slot, so children weren't spaced). The `modalSheet/font*` tokens are unused.
- Page type (`modalSheet/bg` → `ContentSheet/background/color`, collection “Page type”, default MainPage): MainPage `#ffffff`, SubPage `#ffffff`, JioPlus `#f5f5f5`. The other `modalSheet/*` tokens have one mode. Since c1fa197 (#255) the sheet drops Page type (and Color Mode Dark) from the modes it passes to slot children, except an AppBar, which keeps Page type; a child's own modes are still merged over them. So under JioPlus: Text stays dark (`rgb(0,0,0)`); AppBar SubPage turns transparent with a dark title; and when the HelloJio Input's pill colour matches the sheet (`#f5f5f5`), the sheet paints the pill with the light popup surface (white), keeping its `#f5f5f5` border, unless the input sets `jioPlus`. MainPage is unchanged: a white sheet with a `#f5f5f5` pill. The sheet does this only for children it can see: its direct slot children, fragments, and their `children` props. A consumer's own component in the slot gets the modes without Page type, but an AppBar or a HelloJio Input it renders inside isn't recognised: the AppBar loses Page type (white on the grey sheet) and the pill isn't repainted, so it still matches the sheet. Before c1fa197 every child got JioPlus: Text turned `#ffffff` and the pill matched the sheet. JioDot and IconButton (Emphasis Low) don't change. In Figma “Page type” is a remote variable collection, not a property or variant; the component resolves to MainPage. Storybook's Default story has a Page type control (`ModalSheet.stories.tsx:47, 56, 70, 206`).
- `enableDismissGesture` (default true; `ModalSheet.tsx:206`) gates only the drag (React Native `PanResponder`, `:394-398`, `:481`) and the “Drag down to dismiss” hint (`:478-480`). The scrim (`onOverlayPress`) and a close button in the slot still work; with the drag off the sheet never calls `onRequestClose`. Storybook has it as a control (`ModalSheet.stories.tsx:52-58, 75-78, 204`); Figma doesn't mention it.
- Classification. Designer-configurable: the slot content, fill or fit content, the scrim, Page type, top inset, whether a drag closes it (`enableDismissGesture`). System-driven: the slide and spring, the drag threshold. Developer-only: `visible`, `onRequestClose`, `onOverlayPress`, `onDismissed`, `presentationProgress` and the page-stack helpers, `style`, `testID`.

## Browser measurements (Chrome, react-native-web 0.21.2, Light)

- In flow, `fillHeight={false}`, an AppBar, one line of Text, and a HelloJio Input in a 360 px column: 360 × 183, padding 12/8/32/8, radius 20, white, children 12 px apart (13 October, c1fa197; before, 0 px apart).
- Presented with `topInset={40}` and `fillHeight` (c1fa197): the sheet shortens by 40 and its bottom stays in the frame (the guide's 320 px stage: top 41, bottom 1 inside the 1 px border, 278 tall). With `fillHeight={false}` it docks to the bottom and ignores the inset. Before c1fa197 the sheet kept its full height, so its bottom 40 px fell outside the frame.
- The scrim covers the frame; tapping it calls `onOverlayPress`. The AppBar renders as a heading (`h1`) with a back button unless `leadingSlot` is set; the close IconButton is 40 × 40.
- After closing (c1fa197), the hidden sheet's host is `inert` and `aria-hidden`, and its controls get `tabindex="-1"`, so Tab skips them and the frame doesn't scroll. Before, Tab reached them and scrolled the frame. React logs a development warning for the string `inert` value (production builds don't).
- Opening motion, measured frame by frame in Chrome (12 October 2026): the published Storybook Default story travels 860 px, overshoots 0.4 px, and settles in about 410 ms. Before this fix the guide's In context sheet travelled 900 px, overshot by 125 px, bounced back 14 px, and snapped 1 px at 430 ms. After it, the same sheet follows Storybook's curve (see the third fix loop below).

## Accessibility (web)

- `role="dialog"`, named only by `accessibilityLabel` or a slot child's `title` prop (the guide's App Bar has none, so its dialogs are unnamed); no `aria-modal`. Focus isn't moved into it, kept in it, or returned. Escape closes it except from a text input. The “Drag down to dismiss” hint isn't exposed on the web. A hidden sheet is out of the Tab order and the accessibility tree.
- The scrim is a button named “Dismiss overlay” (fixed English). Close needs a named IconButton in the slot.

## Review 11 October 2026 (fix loop)

- Marcin: dark corners on all four corners; the second screen (Without a scrim) looked broken; “look how it’s made in Storybook”. Cause: the guide hosted the sheet in a white frame with the 70% scrim filling the same box, so the scrim showed as dark crescents between the sheet’s four 20 px corners and the frame; without a scrim, the white sheet sat on a white page with nothing between them. The sheet itself matches Figma (one radius 20 on all corners) and renders the same in Storybook. Fix: the kit’s `ScreenFrame receded` gives the frame Storybook’s black stage and steps the page back by `MODAL_SHEET_PAGE_STACK` (at that time the site's animation stub couldn't run `useModalSheetPageStackStyle`: its `interpolate` returned the progress unchanged; fixed in the third loop).

## Review 11 October 2026, second fix loop (Astra's three issues)

- “Fills the screen examples: black crescents still show at the sheet's rounded corners.” Docs mistake. The kit's screen frame clipped at 16 px (15 px inside its border) while the sheet's corners are 20 px, so the black stage showed at every corner where the sheet met the frame: all four on a filled sheet, the bottom two on a fitted one. Neither source shows that: Storybook's frame cuts the sheet's bottom off (#234) and Figma's device composition puts the sheet's bottom on white to the screen edge. Fix: the stacked frame's corners are 32 px, rounder than the sheet's, like a phone screen's; the corner wedges are gone (checked at 2× in Chrome).
- “Configuration: page types MainPage, SubPage and JioPlus aren't shown.” Docs mistake, plus a component bug. The guide also wrapped the slot content in a helper that swallowed the modes the sheet passes to its slot, so Page type would never have reached the children. The slot content now takes the sheet's modes. MainPage and SubPage render the same white sheet; JioPlus renders a `#f5f5f5` sheet with white body Text and an input pill that blends into it (the same pill in Storybook's Default story with Page type JioPlus): #255.
- “Dismissal: no explanation of drag-to-dismiss turned off (enableDismissGesture).” Docs mistake: it is a designer choice (whether a drag can close the sheet), and the brief had excluded it as developer-only.

## Review 12 October 2026, third fix loop (animation)

- Marcin: “Animation works differently, so it looks really odd, like we have some kind of spring animation. We should use the same version that we have in the code.” Docs mistake. This site replaces `react-native-reanimated` with a web stub (`src/web-stubs/reanimated.ts`, aliased in `vite.config.ts`). Its `withSpring` ignored the config and always played a fixed 420 ms curve, `1 − e^(−7p)·cos(10p)`, which overshoots about 11 %; its `withTiming` ignored the easing; its `interpolate` returned the input. The package's spring (damping 32, stiffness 300, mass 1) doesn't bounce, and Storybook, which runs the real Reanimated, shows no bounce (measurements above).
- Fix: the stub now runs Reanimated 3's own spring step (`animation/spring.ts`, `springUtils.ts`: the under- and critically damped formulas, 64 ms frame cap, rest thresholds, overshoot clamping, defaults damping 10, stiffness 100, mass 1), `withTiming` with its easing (default `Easing.inOut(Easing.quad)`), and a real `Easing` and `interpolate`. The kit's `ScreenFrame receded` now takes the sheet's `presentationProgress` and steps the page back through the package's `useModalSheetPageStackStyle`, as Storybook's story does, in step with the sheet and the drag, instead of a 300 ms CSS transition.
- Also affected, now as the package animates them: Drawer and ContentSheet (the same spring, no longer bouncing); ListGroup's shift (default easing); Section, TextInput, Spinner, and SkeletonGroup timings (their own easings). Popup uses React Native's `Animated`, not this stub.

## Limits

- Light only (Color Mode doesn't change the sheet; slot content is Light). The page uses `topInset={0}` except where it shows the inset.
- Not shown as designer settings: `presentationProgress` and the page-stack hook (the kit wires them as Storybook does), `style`.
- Page type JioPlus is shown as it ships since c1fa197: dark text and a white HelloJio pill on the grey sheet.
