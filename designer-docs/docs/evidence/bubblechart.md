# Bubble Chart source evidence

Package, Figma, and Storybook evidence for the Bubble Chart guide (board ticket #121, Design documentation — Marcin; Storybook coverage — Biscuit).

## Checked

Checked 19 October 2026. Installed `jfs-components` is `0.1.78` from mirror tag `v0.1.78-a116616` (Biscuit's `main` at a116616). `BubbleChart.tsx`, `bubblePacking.ts`, and `ClusterBubble.tsx` are byte-identical to Biscuit's clone; his newer `main` (c7d3348) doesn't touch them. ## Sources

- Figma: the ticket's link (Coin Subcomponents `27:854`) is the Stepper Item page, not this component. Neither Figma file has a Bubble Chart. The Coin Components Library has [clusterBubble](https://www.figma.com/design/3z7bmhA73Ls7j8Eu4qhYhE/Coin-Components-Library?node-id=4920-12956) (page Data viz), a set with `Property 1` = Default (159 × 159 disc, value and label inside, white) and Freeform (a 33 px dot with a black value and label outside), plus a `slot` property. Its text is fixed at value 20/22 weight 800 and label 10/10 weight 400; its fill aliases `dataViz/emphasis/bg`, so Appearance / DataViz and Emphasis / DataViz drive it. Code Connect maps it to `ClusterBubble.tsx`. Nothing in Figma defines the packing, the size range, or label placement.
- Storybook (published `index.json`): `components-bubblechart--default`, `--uniform`, `--all-labels-outside`, `--skewed`, `--constrained`, `--wide-pool`, `--pressable`, `--docs`; frames are white `View`s 480 px wide with 16 px padding, layout centred. Storybook's actions addon injects `onBubblePress` into every story (`argTypesRegex '^on[A-Z].*'`), so every story's bubbles are buttons. The story arg `Color Mode: 'Light'` overrides the toolbar. The hosted Storybook's token data differs from the installed package for some collections (Neutral fills are `#f5f5f5` there, `#cccfd1` installed); the docs use the installed values.
- Hosted results: Default clips a "Recommended" outside label to "Recommende" (8.4 px past the edge); All Labels Outside, Constrained, and Wide Pool show overlapping labels; Wide Pool has two bubble pairs overlapping by 1.9 px; the smallest bubble-to-bubble gap is under the configured 8 px in every story. Uniform and Skewed are clean.

## Contract

- Exports: `BubbleChart`, `BubbleChartProps`, `BubbleDatum` (and `ClusterBubble` with its types) from the package root (`components/index.ts:268-273`).
- `BubbleDatum`: `value` (number, required), `display` (bold text; defaults to `String(value)`), `label` (caption), `appearance` (an Appearance / DataViz mode; cycles if omitted), `color` (hard fill override), `labelPlacement`, `accessibilityLabel`, `id`.
- Chart props (defaults `BubbleChart.tsx:125-140`): `data`, `minBubbleSize` 48, `maxBubbleSize` 170, `gap` 8, `labelGap` (= gap), `height` (derived), `labelPlacement` `'auto'`, `autoInsideMinSize` 88, `appearanceCycle` Primary, Secondary, Tertiary, Quaternary, Quinary, Senary, Neutral (an eighth item repeats), `iterations` 500, `onBubblePress(datum, index)`, `modes`, `style`, `accessibilityLabel`. No testID, legend, axes, tooltip, animation, selected state, or empty state.
- Size: `scaleRadii` (`bubblePacking.ts:37-61`) maps sqrt(value) between the smallest and largest value onto minBubbleSize–maxBubbleSize. The smallest value is always minBubbleSize and the largest maxBubbleSize, whatever their ratio: 60 and 40 draw at 166.6 and 47 px (about 12.6 : 1 in area). Equal values all draw at maxBubbleSize. Only with a 0 in the data does area follow the value. The mdx and JSDoc say the area follows the value.
- Width and height: the root is `width: '100%'`, `overflow: hidden`, `role="img"`; it is 0 px tall until it measures its width. Without `height` it picks one from the bubbles' area, between 0.6 and 1.35 × the width. If the bubbles don't fit (a fixed `height`, a narrow host) every radius shrinks, down to 6 px: `height={120}` gave bubbles of 12 px, below minBubbleSize.
- Placement: a deterministic force simulation packs big bubbles in the middle and outside-labelled ones at the edge. Positions carry no meaning. `gap` is not guaranteed (a wall clamp runs after the collision step).
- Labels: `auto` puts the value and label inside bubbles at least `autoInsideMinSize` (88 px) wide after fitting, outside otherwise, on whichever of bottom, right, left, top scores best. Inside text scales with the bubble (value 17 % of the diameter, 13–48 px, weight 700; label 8.5 %, 10–18 px, weight 400), centred with 8 px side padding, clamped to two lines and clipped by the circle. Outside text is value 24 px and label 14 px. The room reserved for outside labels uses an estimate that is too small for 14 px captions (“Recommended”: 92.4 estimated, 100.6 measured), so long outside captions can be clipped at the chart edge; with `auto` and outside labels, labels can collide with each other and with bubbles as items grow (at 343 px: clean up to 3–4 items with one dominant value). `labelPlacement="inside"` was clean at 311–520 px with 2–8 items.
- Colour: each bubble's fill is `dataViz/bg` for its own appearance and the chart's Emphasis / DataViz (Light, High: Primary `#5d00b5`, Secondary `#b84fbd`, Tertiary `#b9beff`, Quaternary `#026b9a`, Quinary `#4cbfac`, Senary `#cea15a`, Neutral `#cccfd1`; Medium and Low are progressively paler, Low Primary `#ede7ff`). Inside text is `#0f0d0a` or white by fill luminance (> 0.6 → dark); white on Secondary High is 4.29 : 1. Outside text is `text/foreground` (black in Light).
- Modes: Emphasis / DataViz recolours every fill (one emphasis per chart). Appearance / DataViz in the chart's `modes` does nothing (each bubble's own appearance wins, `ClusterBubble.tsx:169-172`); Context does nothing visible; Page type and Text Appearance only recolour outside labels (JioPlus white). `modes` reaches every Cluster Bubble; a `JFSThemeProvider` Color Mode reaches them unless `modes` overrides it.
- Interaction: with `onBubblePress` each bubble is a `<button>` named “<display>, <label>” (when both are text) that dims to 0.85 opacity while pressed and calls back with the datum and index; there is no selected look. Without it each bubble is `role="img"` with the same name. The buttons sit inside the root's `role="img"`, and the root has no name unless `accessibilityLabel` is passed.
- Classification. Designer-configurable: the items and their display text and captions, how many there are, label placement (chart and per item), Emphasis / DataViz, a per-item appearance (to highlight one), the bubble size range, pressable bubbles. System-driven: positions, sizes from rank, inside/outside under auto, label side, text sizes and colours, the height. Developer-only: `onBubblePress` wiring, `accessibilityLabel`, `iterations`, `labelGap`, `autoInsideMinSize`, `appearanceCycle`, `color`, `style`.

## Usages

No other package component or story renders BubbleChart. `AreaLineChart.mdx:28,85` calls it a “scatter / bubble plot” of free x/y bubbles, which it isn't. The stories' data is a portfolio split (“72% Equity”, “8% Gold”…) and a “Recommended” layout.

## Limits

- Not shown: Color Mode, Page type, Text Appearance, Context, Appearance / DataViz in the chart's modes, `color` overrides, `iterations`, `labelGap`, `appearanceCycle`, `style`.
- Not implied: that bubble area is proportional to the value, that bubbles never overlap or clip, that positions mean anything, a selected state, a legend, tooltips, or animation.
